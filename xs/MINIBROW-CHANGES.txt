Changes made for MiniBrow (Open Watcom C / Windows 95)
------------------------------------------------------
Each change is marked with a "MiniBrow:" comment.

  xs/sources/xsBigInt.c
      Four "txBigInt digit = { .sign=0, .size=1, .data=data };" initializers
      rewritten as assignments (Open Watcom rejects non-constant aggregate
      initializers).

  xs/sources/xsPlatforms.c
      "#if _MSC_VER < 1800" changed to
      "#if defined(_MSC_VER) && _MSC_VER < 1800" so that other compilers do
      not compile the old-MSVC replacements.

  xs/sources/xsAtomics.c
      "#elif mxWindows" changed to "#elif mxWindows && !defined(mxW95)" so that
      the Windows 95 build does not use condition variables (Vista and later).
      Shared-memory threads (Atomics.wait across agents) are therefore not
      available.

  xs/sources/xsre.c (fxCharSetRange)
      Without the u or v flag, a class escape at either end of a range such as
      [\w-%] now makes the hyphen a literal, as ECMAScript Annex B requires.
      XS reported "invalid range", which rejected the whole script.

  xs/sources/xsMath.c (fx_Math_toInteger)
  xs/sources/xsCommon.c (fxNumberToIndex, fxStringToIndex)
  xs/sources/xsArray.c (length check)
  xs/sources/xsRun.c (fxIsSameValue)
      Added explicit NaN checks (c_isnan) before comparing a double with
      another number. Code generated by Open Watcom for the x87 treats an
      unordered comparison (NaN == x) as equal, which turned Number(undefined)
      into -2147483648 and made [0].includes(NaN) true.

New files (part of MiniBrow, same license as XS: LGPL-3.0-or-later)
  xs/w95/w95pre.h   forced include: selects the platform header, works around
                    Watcom keywords ("huge") and fdlibm settings
  xs/w95/w95_xs.h   platform definitions for Windows 95 / Open Watcom
  xs/w95/w95_xs.c   memory accounting with a per-page limit, fxAbort (ignores
                    unhandled promise rejections), fxQueuePromiseJobs,
                    _BitScanReverse, a seeded Math.random generator (w95_rand),
                    sqrt / log2 wrappers that return NaN for negative input
                    (the Watcom library returns 0 / -Infinity)

Rebuilding / replacing XS
-------------------------
The whole MiniBrow source is distributed with the program. To use a modified
XS, change the files under xs/ and run "wmake clean" then "wmake" with
Open Watcom C 2.0; xs.mak builds xs.lib, which is linked into minibrow.exe.
